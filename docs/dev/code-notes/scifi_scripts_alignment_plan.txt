--------------------------------------------------------------------
Today's session heavily refactored common_scripts (naming consistency,

scifi_scripts was deliberately left untouched throughout except for one

There are exactly two known, real misalignments left, both already
flagged and deliberately deferred earlier today ("lo faremo poi" / "lo
sistemeremo poi"):

1) BREAKING: common_scripts/power/feb_crate.py's
   build_feb_bringup_sequence() was merged from an explicit-args
   signature (feb_id, client, link_feb, equipment_name, feb_index, ...)
   into a single duck-typed-object signature (feb, ...) expecting
   feb.get_id() / feb.client / feb.get_link_feb() / feb.get_station() /
   feb.get_number(). scifi_scripts/actions/bringup_declaration.py's
   build_feb_crate_sequences() still calls the old 5-arg form, confirmed
   broken via the scifi test suite (Docs/devolpment/code/tests/
   test_bringup.py): AttributeError: 'str' object has no attribute
   'client'.

2) NON-BREAKING DUPLICATION: scifi_scripts/detector/feb.py's
   LV_EQUIPMENT_NAME = "DCDCCrates" duplicates a literal that already
   exists as equipment_names.EquipmentName.DCDC_CRATES in
   common_scripts/equipment/names.py - the shared enum built
   specifically to eliminate this.

Governing principle set by the user this session: "SciFi's own classes
will be changed to conform to Pixel's shape, not the reverse." So the
fix is to extend scifi's real Feb class to satisfy the same duck-type
contract PixelFeb already satisfies - not to write a local
wrapper/adapter around it.
