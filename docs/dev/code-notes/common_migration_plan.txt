     partitions only, Action's checks all of them; Calibration's nests
     the step data under {"Power": readables}, Action's does not nest
     at all - i.e. TODAY ACTION AND CALIBRATION STEP RESULTS ALREADY
     USE TWO DIFFERENT SCHEMAS for the same kind of data; Calibration's
     has an optional LVDS-stats merge, Action's has none. This must be
     resolved (not just moved) as part of unifying under OperationBase -
     pick one schema, one selection-filtering rule, and fold LVDS-merge
     in as an optional argument available to both. This is real design
     work, not a mechanical merge.

  NOT decided here, stays open: whether calibration parameters keep

  version of GAP 4. ActionFactory.perform_action() (actionfactory.py:
  44-46) calls `res = action.perform(); action.post_perform(res)` with
  NO try/finally - if perform() raises partway through (a real
  possibility: it does live ODB reads/writes, wait-for-condition loops
  with timeouts, etc.), post_perform() - the ONLY place that currently
  calls save_final() for anything - never runs. So the "does the saver
  always get closed" problem (5c) exists to solve is not just "GAP 4 in
  calibrations", it is "success-path-only closing in general" - it
  affects the ActionFactory path today too, on any exception, not only
  on a clean-but-unsuccessful return. This makes the case for (5c)'s
  try/finally stronger, not just tidier.
