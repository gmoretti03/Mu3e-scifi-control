The design went through several pivots in one session (all kept below
for the reasoning trail, but this section is the one to trust if it
conflicts with anything further down):

1. NOT a multi-FEB automated sweep. Concluded a JS-page-driven loop
   over thousands of DAC combinations isn't realistic (browser-tab-
   dependent, no backend resilience - see "ARCHITECTURE CHANGE"
   section below for why no PySequencer/Python is involved at all).
   FINAL: the page is a MANUAL, SINGLE-STEP tool. The operator sets one
   FEB + one ASIC (+ the 3 DAC values) and presses an action that runs
   ONE iteration of what used to be the loop body (mask -> set SMB_
   control/asic -> zero DACs -> set chosen DACs -> Set FEBs Into
   Running -> wait 1s -> Set FEBs Into Idle -> read_hist -> read FCTM
   temp) - then the operator repeats manually for the next combination
   they want to try. No automated iteration, no Start/Stop/Pause state
   machine, no PySequencer.
2. SELECTION MODEL, changed to match #1: a single active FEB+ASIC
   target, NOT the multi-FEB checkbox list (`pllSelectedFebs`) ScanVbr/
   ScanThr use - that model was for an automated sweep across selected
   FEBs, which no longer exists. `selected_febs` in ODB is likely not
   needed anymore for PllTest specifically (not yet removed from ODB,
   see "STILL OPEN" below).
3. SECTION PLACEMENT, changed AGAIN: given #1/#2, this is a live manual
   diagnostic/probing tool, not a calibration producing a persisted
   physics constant the way ScanVbr/ScanThr do - so it goes back to
   CONFIGURATION (reversing the Calibration-vs-Configuration reversal
   earlier in this same doc). This matches the ORIGINAL 2026-08-14
   decision, but arrived at for a better reason this time (the real
   mechanism turned out to be a manual per-step tool, not guessed at).
4. PERSISTENCE EXCEPTION, explicit: Configuration's established
   philosophy is "nothing written/saved to ODB, fully live" (2026-08-14
   decision, still true for everything else in Configuration). PLL
   TEST IS A DELIBERATE EXCEPTION to that rule: the user explicitly
   wants the per-step trace (Temp0/Temp1/Verdict) and the last
   histogram PERSISTED to ODB (not just shown live and discarded), so
   the temperature-vs-lock correlation can be reviewed later after
   leaving the page. Reason given: "teniamola persistita, così vediamo
   la correlazione dopo".
5. ODB LOCATION: stays exactly where already designed and confirmed -
   `/CosmicRun/Calibration/SciFi/PllTest/<FEB>/...` (schema below,
   still valid). NOT moved to a Configuration-owned path, even though
   the PAGE TAB itself moves to SciFi_Configuration.js. Precedent for
   this split already exists today: SciFi_Configuration.js already
   reads `CFG_CAL_ODB_BASE + "/PllTest"` (= this same path) read-only

   tab reading/writing a `/CosmicRun/Calibration/...` path is not a new

6. ParametersUsed CHANGES SHAPE (not yet re-confirmed with the user,
