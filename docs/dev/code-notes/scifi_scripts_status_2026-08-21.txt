3. WHAT'S DELIBERATELY DIFFERENT FROM PIXEL (verified, not accidental)
--------------------------------------------------------------------
- Object model depth: Feb -> Asic -> Channel (3 levels) vs pixel's
  flat Feb-index -> Chip (2 levels). Confirmed via a dedicated
  exploration: MuTRiG ASICs have 32 independently-thresholded/
  maskable SiPM channels each (real hardware need, exercised by
  thr_scan.py's per-channel bulk writes); Mupix chips have zero
  sub-channel concept at all (grep confirms "channel" appears nowhere
  in pixel's chip.py/detector.py). Do NOT flatten this.
- HV architecture: ScifiHv's shared side-groups (US/DS Top/Bottom,
  resolved via MSCB host string per HV channel) have no pixel
  equivalent - pixel does HV per-partition, scifi's HV hardware is
  wired as 4 shared groups spanning multiple modules each. No common
  base makes sense here.
- Calibration-level selection: thr_scan.py/vbr_scan.py select modules/
  ASICs via an ODB CSV (selected_asics/selected_modules) + regex-
  parsed folder names, NOT pixel's chip.get_user_selected()/
  mask_all_chips() boolean-mask model. This was explicitly reviewed
  and confirmed as SciFi's own valid design in the 2026-07-23 Marius
  call (page structure + calibration granularity both CONFIRMED) -
  not an accident, not scheduled to converge.
- Actions dispatch: scifi's bring-up scripts call actions/
  poweractions.py & febactions.py functions directly and
  imperatively - no ActionBase/OperationFactoryBase subclassing at
  all. Verified this is NOT actually a scifi gap relative to a working
  pixel pattern: pixel's own ActionBase/actionfactory.py/daqactions.py/
  febactions.py/poweractions.py machinery has NO real sequencer entry
  point either (no run_action.py - only exercised by pixel's own
  test3.py). Chasing this pattern now would mean building unproven
  architecture on both sides at once - deliberately not done.
- calib_run.py's CalibrationExecute/CalibrationFactory.
  perform_calibration() ODB-driven dispatch (by CurrentCalibration
  value) is fully built and tested but genuinely unused - scifi's 3
  real calibration buttons each always run one hardcoded calibration,
  not an ODB-selected one. Left as dead-but-tested code rather than
  forcing scripts through it, since doing so would silently change
  which calibration each real page button actually triggers.
