  Re-read mdev_hv4.cxx, mdev_tdk.cxx, mdev_mpdc.cxx one more time: HV and
  PowerDistStaging are now 100% Enabled-only, matching the .cxx exactly
  (no other condition blocks a write in either driver). TDK's one
  deliberate divergence (Allow write access demoted to message) was
  double-checked too: Interlock was NEVER a software gate in mdev_tdk.cxx
  to begin with (not checked in either watch callback - it's a pure

  divergence at all.

  Also checked mdev_pdcc.cxx (DCDCCrates/LV) for the first time this pass
  - found a REAL STRUCTURAL DIFFERENCE from the other three drivers:
  Crate On/Reset/Clear Fault/Channel On/Voltage Adjust watch callbacks
  check `m_mscb[dev] != nullptr`, NOT the live "Enabled" ODB value.
  m_mscb[dev] is assigned ONCE in init() - nullptr forever if Enabled was
  false at frontend startup, a real connection forever otherwise. Toggling
  Enabled AFTER startup has NO EFFECT on whether these writes reach
  hardware - the opposite situation from TDK/HV/PowerDistStaging, where
  Enabled is re-read live on every single write. Gating LV on Enabled the
  same way as the others would be MORE restrictive than reality (would
  block writes that would actually still work). Decided: no gate added for
  DCDC crates - matches "no gate" that was already the status quo there.
