0) Why this matters now - the real deadline
------------------------------------------------------------------
The whole Mu3e detector is being assembled right now. October 2026 is
when the whole experiment starts - the first real, proper physics run.
This is not a "clean up when there's time" project. The control
software (PySequencer scripts + whatever control page ends up driving
them) needs to be trustworthy by then.

Framing for the conversation with Marius: this is NOT "fixing bad code."
Scifi-monitor.js was written when SciFi had 2 LV channels and 4 HV
channels in a small test setup - hardcoding indices at that scale was
proportionate, not a mistake. The stale-index bug found this session
(12 real LV channels vs 2 hardcoded, 32 real HV vs 4 hardcoded) is the
detector having grown past the scale the code was written for. The
pixel/VTX group had to build real abstraction (ConfigManager, declarative
UI descriptors) from day one because pixel has 8 layers - a bigger
topology forced better architecture early. SciFi is now going through
the same growth pixel already went through. Open with this framing, not
a critique of existing code.


1) What's already built (Python / PySequencer side)
------------------------------------------------------------------
Repo: scifi-userfiles (scripts/ - see this repo's own README.md for the
authoritative, current layout/rules). Summary as of 2026-07-10:

  - common/scifi_topology.py, common/asic_control.py: shared topology
    reading and ASIC-config primitives. equipment_prefix-aware
    (SciFiLabor vs SciFiFibre), auto-detected via
    detect_equipment_prefix() (seq.odb_exists() - the two trees are
    mutually exclusive per machine, no human choice needed).
  - scan_thr/: full threshold-scan task (scan_thr.py, rate_scan.py,
    threshold_finding.py, root_writer.py, plot_manager.py,
    apply_thr.py). Optional 0.5/1.5/2.5pe auto-calibration. Auto-detects
    site. apply_thr.py warns (doesn't skip) on low-confidence
    calibration rows (chosen_score < 0.55).
  - scan_vbr/: IV scan + VBR (breakdown voltage) finding
    (scan_vbr.py, iv_scan.py, vbr_finding.py, root_writer.py,
    plot_manager.py, apply_vbr.py - DRAFT, not reviewed with Marius).
    VBR extraction: peak of d(log10 I)/dV, Gaussian-refined, with a
    confidence check (min_peak_prominence) to reject noise-driven false
    positives. apply_vbr.py mirrors apply_thr.py's warn-don't-skip
    pattern.
  - feb_power.py / lv_power.py / hv_power.py: pure on/off executors for
    FEB power, SciFi LV (DCDCCrates), SciFi HV. All discover their real
    channels dynamically (by ODB Names[] pattern), not hardcoded
    indices - this is what caught the stale-index bug. No per-channel
    selection - that's explicitly deferred to a future masking editor
    (see section 3).
  - DCDCCrates/HV only exist on mu3ebe (no Labor/test copy) - those two
    scripts (and scan_vbr's HV sweep) can only be tested for real there,
    coordinated via the beamtime channel.

  Not yet built (from the original ~19-script list agreed with Marius):
  configure_pll, configure_0pe5/1pe5/2pe5/long/prbs, mask_all_ch/
  unmask_all_ch, reset_datapath/reset_asics, optimizeRates, sorter_tuning,
  sorter_scan, create_shift_report/end_of_shift_report. See section 5 for
  which of these might already be adequately covered by existing manual
  tools and not need PySequencer automation at all.

2.1) Scifi-monitor.js (1021 lines, 32 functions) - deep-read 2026-07-10
  - Its OWN mask editor (renderGrid()/toggleChannelMask()) is a real,
    working, correctly-targeted (SciFiLabor) per-channel grid, color-
    coded by live rate, click-to-edit via MIDAS's own modbvalue elements.
    Different from and more mature than scifi.html's ring-view mask
    editor (see 2.2) - don't conflate the two when discussing this with
    Marius.
  - create_shift_report()/end_of_shift_report(): a real, working
    checklist (FEBsOn, SWBOn, LV0/1, HV0/1, IVScan0/1, PllTestDone,
    RateScan, RateTuning, SorterTuning) + browser-side .txt export.
    create_shift_report() is the actual origin of the
    IVStart=50/IVEnd=58/IVIdx0=22/IVIdx1=23 defaults found in
    SciFiFibre's ShiftReport at the start of this investigation.
  - optimizeRates(): a COMPLETE, working iterative auto-tuning
    algorithm - 10 steps, per-channel rate-based tthresh/offset/mask
    adjustment. The reference implementation for the still-unbuilt
    optimizeRates script - port this logic, don't redesign from
    scratch.
  - sorter_tuning()/sorter_scan()/get_sorter_value(): real per-channel
    A/B masking test (keep masked only if it's strictly better on
    sorter efficiency + in-time-fraction) and a real 2D parameter sweep
    (sorter_delay x lapse_delay, 200 combinations) - same
    sweep/measure/store shape as our scan_thr/scan_vbr pattern, a good
    concrete precedent. CAVEAT: sorter_tuning()'s outer loop only runs
    for sorter=1 (range(1,2) - sorter=0's branch never executes) -
    looks like a possible incomplete/WIP implementation, only covers
    half the channel range. ASK Marius whether this is a known gap
    before treating it as a correct reference.
  - Both create_shift_report and end_of_shift_report/optimizeRates/
    sorter_scan write results into ShiftReport-based ODB arrays or
    generate browser-only downloads - no server-side, shared archive of
    results the way our .root-file convention gives us.

TWO IMPLEMENTATION PITFALLS, found while building the mockup - worth
flagging explicitly so whoever implements the real page doesn't hit the
same two:

      select-all checkbox to match (not just the individual row
      checkboxes) - otherwise clicking "select all" leaves every group
      header's own checkbox visually unchecked despite every row inside
      being checked, an inconsistent state. Fix is mechanical (the
      table-wide handler needs to touch group checkboxes too), but easy
      to miss if group selection is wired independently from table-wide
      selection.
  (2) A group's expand/collapse must NOT touch each row's own detail-
      panel state (FEB's crate/FEB temperatures, LV's sense/temperature/
      fault-flag panel, both from 3.1). If the expand/collapse toggle is
      implemented by adding one shared "visible" class to every element
      tagged as belonging to that group, and a row's OWN detail panel
      shares that same tag (it's still "part of the group" structurally),
      expanding the group will incorrectly force every row's detail open
      too, with no way to look at just the summary rows. The two
      concerns need separate visibility state: "is this row's group
      open" (controls the summary rows only) vs "did the user click THIS
      row to see its own detail" (independent, only ever set by that
      row's own click) - collapsing a group should still force-close any
      detail left open inside it, but expanding a group must never
      force one open.
